# 01 - 下发订单流程文档

> 文件：`src/views/placeOrder/index.vue`
> 接口：`POST /order/new`（`orderNew`）

---

## 一、整体结构

下发订单页面根据**车辆类型**分为两大分支，所有字段、校验、提交逻辑完全独立：

```
车辆类型
├── CTU 料箱机器人（vehicleType = 'ctu'）
│   ├── 出库（ctu_out）
│   ├── 入库（ctu_in）
│   └── 移库（ctu_move）
└── AGV 叉车机器人（vehicleType = 'agv'，默认）
    ├── 点到点（taskType = 1）
    ├── 点到区域（taskType = 2）
    └── 区域到点（taskType = 3）
```

---

## 二、公共初始化逻辑

页面挂载时执行：

| 操作 | 说明 |
|---|---|
| `GetAreaInfo()` | 按当前 `vehicleType` 向后端请求库区列表（传 `vehicleType` 参数，后端过滤） |
| `getAllLocation()` | 拉取全量库位数据（`allLocationList`），用于扫码校验 |

**库区过滤规则（后端实现）：**
- `vehicleType = 'ctu'` → 返回库区名称以 `"库区"` 结尾的库区
- `vehicleType = 'agv'` → 返回库区名称不以 `"库区"` 结尾的库区

**切换车辆类型时：** 重置所有数据，重新请求对应类型的库区列表，切换任务类型默认值。

## 三、CTU 料箱机器人

### 3.1 任务类型列表

| 值 | 显示文字 |
|---|---|
| `ctu_out` | 出库（默认） |
| `ctu_in` | 入库 |
| `ctu_move` | 移库 |

### 3.2 固定常量

| 常量 | 值 | 说明 |
|---|---|---|
| `CTU_FIXED_LOCATION` | `R50A01011` | 固定对接库位（入库的开始库位 / 出库的目的库位） |
| `CTU_MAX_LOCATIONS` | `6` | 单次最多选择的库位/料箱数量 |

### 3.3 出库（ctu_out）

**界面显示：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 开始库区 | 下拉选择 | 从 CTU 库区列表中选择 |
| 开始库位 | 多选列表 + 扫码 | 最多 6 个，选择有货（status=2）的库位 |
| 目的库位 | 只读文本 | 固定为 `R50A01011`，不可修改 |

**库位选择方式：**
1. 先选开始库区 → 自动加载该库区下有货（status=2）的库位列表 → 点击选中
2. 直接扫码输入 → 校验库位存在、属于CTU库区、有货、未重复、未超上限

**提交校验：**
- 开始库区不能为空
- 开始库位至少选 1 个

**提交数据结构：**
```json
{
  "type": "ctu_out",
  "orderCode": "ZTEV1_TASK1",
  "vehicleType": "ctu",
  "startArea": "用户选择的开始库区编码",
  "startLocations": ["库位1", "库位2", "..."],
  "endArea": null,
  "endLocation": "R50A01011",
  "endLocations": null,
  "boxCode": null,
  "boxCodes": []
}
```

### 3.4 入库（ctu_in）

**界面显示：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 开始库位 | 只读文本 | 固定为 `R50A01011`，不可修改 |
| 目的库区 | 下拉选择 | 从 CTU 库区列表中选择 |
| 目的库位 | 多选列表 + 扫码 | 最多 6 个，选择空闲（status=1）的库位 |
| 料箱编码 | 扫码列表 | 格式：`HB` + 6位数字（如 `HB200001`） |

**库位选择方式：**
1. 先选目的库区 → 自动加载该库区下空闲（status=1）的库位列表 → 点击选中
2. 直接扫码输入 → 校验库位存在、属于CTU库区、空闲、未重复、未超上限

**料箱编码扫码规则：**
- 格式正则：`/^HB\d{6}$/`（HB + 恰好6位数字）
- 格式不符：弹出 Toast 提示（2.5秒自动消失，无需确认）
- 重复添加：弹出 Dialog 提示
- 超出上限：弹出 Dialog 提示

**提交校验：**
- 目的库区不能为空
- 目的库位至少选 1 个
- 料箱编码至少扫 1 个
- **料箱编码数量必须等于目的库位数量**（一一对应）

**提交数据结构：**
```json
{
  "type": "ctu_in",
  "orderCode": "ZTEV1_TASK1",
  "vehicleType": "ctu",
  "startArea": null,
  "startLocation": "R50A01011",
  "startLocations": null,
  "endArea": "用户选择的目的库区编码",
  "endLocations": ["库位1", "库位2", "..."],
  "endLocation": null,
  "boxCode": "HB200001",
  "boxCodes": ["HB200001", "HB200002", "..."]
}
```

### 3.6 CTU 扫码库位校验流程

```
扫码输入库位编码
    ↓
库位是否存在于 allLocationList？
    ├── 否 → 弹窗提示"库位不存在"，清空输入
    └── 是 ↓
        库位是否属于 CTU 库区（startAreaList/endAreaList 中有对应 areaId）？
            ├── 否 → 弹窗提示"不属于CTU库区"，清空输入
            └── 是 ↓
                库位状态是否符合要求？
                    ├── 开始库位：status=2（有货）
                    ├── 目的库位：status=1（空闲）
                    └── 不符合 → 弹窗提示，清空输入
                        ↓
                是否已添加？
                    ├── 是 → 弹窗提示"已添加"，清空输入
                    └── 否 ↓
                        是否超出上限（6个）？
                            ├── 是 → 弹窗提示，清空输入
                            └── 否 → 添加到已选列表，清空输入
```

## 四、AGV 叉车机器人

> **⚠️ 2026-10-09 起：AGV 分支已改为「工序定义驱动」，本节 4.1~4.4 描述的任务类型下拉仅在 CTU 保留。**
>
> - AGV 下单必须先选**工序**（下拉来自后端启用的任务定义），`orderCode` = 所选工序的编码（不再硬编码 `ZTEV1_*`）。
> - 选中工序后，起止**库区**由工序配置锁定填充（`lockDefAreas`）；工序未配起止库区则禁止下发（`defConfigInvalid`）。
> - **起止「库位」均可留空**：不选则由后端在对应库区内自动分配空闲点位
>   （`TaskChildServiceImpl.buildChild`：`orderVo.startArea/endArea` → `getAllocatableLocation`，
>   按 `wcs_warehouse_location.sortNo DESC` 取一个未被临时锁定的 `status=1` 空闲库位）。
> - 因此 AGV 的实际形态是「区 → 可选点」，四个组合（点到点/点到区域/区域到点/区域到区域）由**是否填库位**自然覆盖。

### 4.1 任务类型列表

| 值 | 显示文字 |
|---|---|
| `1` | 点到点（默认） |
| `2` | 点到区域 |
| `3` | 区域到点 |

### 4.2 点到点（taskType = 1）

**界面显示：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 开始库区 | 下拉选择 | 从 AGV 库区列表中选择 |
| 开始库位 | 下拉 + 扫码 | 选择有货（status=2）的库位 |
| 终点库区 | 下拉选择 | 从 AGV 库区列表中选择 |
| 终点库位 | 下拉 + 扫码 | 选择空闲（status=1）的库位 |

**库位选择方式：**
1. 先选库区 → 自动加载该库区下符合状态的库位下拉列表
2. 直接扫码输入 → 校验库位存在、属于AGV库区，自动回填库区

**提交校验（工序定义驱动，现行）：**
- 必须已选工序，且该工序配置了起止库区
- 开始库区、终点库区不能为空
- **开始库位、终点库位均可留空** —— 留空则由后端在对应库区内自动分配空闲点位
  （改动前「开始库位」是必填，这是"只能点到点"的原因）

**提交数据结构：**
```json
{
  "type": 1,
  "orderCode": "ZTEV1_TASK9",
  "vehicleType": "agv",
  "startArea": "开始库区编码",
  "startLocation": "开始库位编码",
  "endArea": "终点库区编码",
  "endLocation": "终点库位编码"
}
```

### 4.5 AGV 扫码库位校验流程

```
扫码输入库位编码
    ↓
库位是否存在于 allLocationList？
    ├── 否 → 不处理（无提示）
    └── 是 ↓
        库位是否属于 AGV 库区（startAreaList/endAreaList 中有对应 areaId）？
            ├── 否 → 弹窗提示"不属于AGV库区"，清空输入
            └── 是 ↓
                自动回填对应库区（data.startArea / data.endArea）
                将库位加入下拉列表（若不存在）
                    ↓
                若任务类型=3（区域到点）：
                    额外调用 GetLocation 校验库位占用状态
```

## 六、提交后重置逻辑

**CTU 提交成功后：**
- 清空所有 data 字段
- 清空已选开始/目的库位列表
- 清空料箱编码列表
- 清空所有扫码输入框
- 任务类型重置为 `ctu_out`（出库）

**AGV 提交成功后：**
- 清空所有 data 字段
- 重新拉取全量库位数据（`getAllLocation`）
